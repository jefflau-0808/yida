# 衣搭（Yida）MVP 产品设计文档

- 版本：v0.2，2026-09-10
- 状态：开发前设计稿；尚未实现或执行应用测试
- 仓库：https://github.com/jefflau-0808/yida
- 产品形态：中文、移动端优先的响应式 Web/PWA
- 核心定位：拍一件衣服，获得搭配灵感；拍过的衣服逐步积累成自己的衣柜。

## 1. 产品目标与已确认需求

用户选好一件上衣后，希望知道适合搭配什么类型、颜色、版型的裤子，以及什么鞋子，不需要提前录入全部衣物。

已确认：
1. 先做浏览器可使用的 Web/PWA，保持简单。
2. 拍一件上衣即可获得裤子、鞋子的具体建议。
3. AI 生成推荐单品的参考图，用户对照自己的衣物寻找相似款。
4. 拍过并确认的衣物自动收录到衣柜，下次直接选用，不必重复拍照。
5. 推荐时能提示哪些推荐单品在衣柜里已有。

产品原则：衣柜是使用过程中积累的结果，不是获得推荐的前置条件。没有录入某件衣服，不代表用户没有它。

首版设计假设：免登录、当前浏览器本地存储；一次以一件上衣为搭配起点；衣柜支持上衣、裤子、鞋子。云备份、跨设备同步以后再做。实施前若希望换手机也能保留衣柜，需要另行加入账号和云存储范围。

## 2. 核心体验

第一次：拍摄上衣 → 确认识别标签并存入衣柜 → 选择场景 → 查看文字建议 → 查看 AI 参考图 → 找自己已有的相似衣物。

后续：从衣柜选择上衣 → 获得推荐 → 优先看到已收录的匹配裤子／鞋子 → 缺少已录入候选时查看 AI 参考款。

例子：
- 输入：白色宽松 T 恤，日常休闲。
- 裤子建议：深蓝色直筒牛仔裤，常规裤长；理由是深浅有层次、整体轮廓协调。
- 鞋子建议：白色低帮运动鞋。
- 若衣柜里有已收录的深蓝直筒牛仔裤，显示真实照片及“衣柜已有”。
- 若没有符合条件的已录入裤子，显示 AI 参考图及“衣柜暂未找到相似款”，不显示“你没有这条裤子”。
- 用户找到相似裤子后可拍照补充衣柜，也可跳过，仍然正常使用推荐。

## 3. 首版范围

| 功能 | MVP 交付 | 边界 |
| --- | --- | --- |
| 拍照／上传 | 一次一件，预览、重新选择、识别标签 | 相册入口始终保留 |
| 标签确认 | 类别、主色、图案、版型；可手动修改 | 不强行识别未知信息 |
| 自动收录 | 用户确认照片与标签后自动保存衣柜 | 原始选图或失败识别不直接入库 |
| 简易衣柜 | 上衣／裤子／鞋子筛选、查看、编辑、删除、选择上衣搭配 | 不做库存数量、穿着日历 |
| 防重复 | 从已有衣柜选用；相同照片检测；相似条目确认 | 不承诺识别所有重拍照片 |
| AI 推荐 | 每次一套，裤子类型／颜色／版型、鞋型／颜色、简短理由 | 点击“换一套”才生成下一套 |
| 已有单品匹配 | 用确认标签查找衣柜候选，展示真实衣物照片 | 未找到不等于用户不拥有 |
| AI 参考图 | 为未匹配的推荐单品生成示意图 | 不是真实商品、试穿或库存 |
| 收藏搭配 | 保存结果快照，查看和移除 | 当前浏览器保存 |
| PWA | 响应式、安装支持、离线查看本地衣柜与收藏 | 新 AI 请求需联网 |

不包含：商城或购买链接、价格比较、真人虚拟试穿、身材推断、自动天气、社交、批量识别整柜衣服、自训练模型、账号与云同步。

## 4. 页面与交互

### 4.1 搭配首页

突出“拍一件上衣，看看怎么搭”，提供“拍照”“相册上传”“从衣柜选择”。
新用户不经过衣柜初始化、登录或长问卷。

上传规格：JPEG、PNG、WebP，原图不超过 10 MB；压缩最长边至 1280px，重新编码去除原始 EXIF。解码失败、超限或不支持 HEIC 时给出明确提示。
选择图片本身不触发外部识别；用户点击“识别衣物”才发送。首次操作说明照片处理用途、本地自动收录规则及第三方服务参与，建议避免人脸等私人信息。

### 4.2 确认并收录

展示照片与可编辑的类别、颜色、图案、版型。上衣细分类覆盖 T 恤、衬衫、卫衣、针织衫和其他上衣；裤子与鞋子使用对应分类。版型不清楚时允许“不确定”。

主按钮：“确认并搭配”，旁边说明“确认后自动存入衣柜”。从衣柜补录裤子、鞋子时按钮为“确认并保存”，不启动以上衣为起点的搭配流程。

保存成功后提示“已收录衣柜，下次可直接选用”。不额外强迫填写名称，默认用“颜色＋类别”命名，可编辑。示例体验图不会自动入库。

识别失败可手动填写必填标签后保存；用户修改后的标签优先。多主体、非衣物或低质量照片提示重拍，不伪装识别成功。首版不推断性别、身材、品牌、价格。

### 4.3 衣柜

导航：“搭配”“衣柜”“收藏”。
卡片显示真实照片、名称和类别，支持筛选、编辑、删除及选中上衣开始搭配。衣柜为空时仍可直接拍照获得建议。
删除需确认；删除衣柜条目不直接删除收藏，但收藏对应单品的“衣柜已有”状态应更新。

防重复策略：
- 已有条目可直接选择，正常情况下不再拍照或识别。
- 相同标准化图片的摘要命中时提示复用已有条目，避免重复保存。
- 重拍后的图片可能不同。基于类别、颜色、图案、版型筛选疑似重复候选，展示缩略图，用户选“使用已有”或“这是另一件，仍然保存”。
- 标签相同不能证明是同一件；不自动合并、覆盖或删除。
- 保存按钮防连点，同一保存请求使用幂等标识，重试不新增第二份。
- 首版只提供轻量重复提示，不实现可靠的跨角度衣物身份识别。

### 4.4 搭配结果

先返回文字，再异步加载参考图，避免等整张图生成后才看到建议。一次展示一套完整建议：

| 区域 | 展示 |
| --- | --- |
| 上衣 | 用户选中的真实照片 |
| 裤子 | 类型、颜色、版型、长度倾向及理由 |
| 鞋子 | 类型、颜色及理由 |
| 衣柜匹配 | 匹配衣物真实照片、具体名称与“衣柜已有”；近似候选明确说明差异 |
| 参考款 | 未匹配单品的 AI 示意图、标签与“AI 搭配参考图” |
| 操作 | 换一套、收藏、补录我找到的相似衣物 |

参考图固定提示：“用于理解款式与颜色，不是实物商品；可用自己的相似衣物替代。”
仅有参考图时不得显示“衣柜已有”，也不得将 AI 图自动存入衣柜。
“补录相似衣物”必须上传或选择用户真实衣物并确认；不能仅凭“我有”按钮创建虚假的实物条目。

若仅一类单品未匹配，只生成该类参考图；两类均未匹配时可生成裤子与鞋子的组合参考图以控制调用量，界面分别显示文字标签。若两类均已匹配，默认使用真实照片，不必生成参考图。参考图不要求包含上衣或人物。

### 4.5 收藏

收藏上衣图片、推荐标签、理由、场景、衣柜候选引用以及已成功生成的参考图快照。
图片尚未完成时可先保存文字，图生成成功后尝试补全收藏；补全失败明确提示，不虚报成功。
参考图保存为本地图片数据，不能只存会过期的供应商链接。
相同起点与相同单品组合避免重复收藏。收藏保留当时方案；“衣柜已有”是动态状态，以当前衣柜是否仍有该条目为准。
所有本地页面提示：“仅保存在当前浏览器，清除浏览器数据可能丢失；暂不支持跨设备同步。”

## 5. AI 与衣柜匹配逻辑

推荐分为三个可独立测试的阶段：
1. 识别照片，获得可编辑标签。
2. 使用已确认上衣标签、场景及有限的相关衣柜候选，生成结构化搭配建议。
3. 应用校验并解析已有条目；为未匹配的推荐单品生成参考图。

场景先支持日常休闲、上班通勤、约会聚会，默认日常休闲。推荐输出固定字段：裤子类型／颜色／版型、鞋型／颜色、理由、可选衣柜条目 ID。缺字段、非法类别或不存在的 ID 不能直接展示为成功结果。

衣柜优先，但不强凑：先按类别、颜色及版型筛选候选，让推荐优先利用合适的已有衣物；没有合适候选时给参考款。默认不把整套衣柜照片发送给模型，仅发送必要的标签及候选 ID。

“衣柜已有”代表链接到真实、已保存的衣柜条目，不代表 AI 参考图中的精确商品被用户拥有。标签近似但有差异时显示“衣柜有相似款：颜色接近／版型不同”，并使用真实照片；让用户决定是否选用。

生成图使用结构化推荐描述，不必将用户原始照片再次发给绘图服务。图像以清晰单品展示为主，不包含品牌标识、人物或文字。生成结果可能偏离描述：人工样本检查颜色与版型一致性，用户可报告“不像推荐”，失败时保留文字并提供明确重试。不能承诺每张图都精确一致。

“换一套”按类型、颜色、版型组合去重；有界重试后仍重复则提示暂时没有新方案。不为换标题重复计费请求，不自动无限生成。

## 6. 状态、性能与异常

- 图片识别、文字推荐、参考图生成使用独立加载与错误状态。
- 文本目标：确认后尽量在 30 秒内得到文字建议；这是待实测目标，参考图可能更慢，不承诺同一时限。
- 更换起点、修改标签或切换场景后，旧请求不得覆盖新结果。
- 图片生成失败不丢弃有效文字和衣柜匹配结果，提供单独重试。
- 保存衣柜失败需显示原因并保留草稿；可继续本次搭配，但明确“尚未存入衣柜”。
- 存储不足不能显示保存成功；已有内容仍可读取。
- 无网络或 AI 未配置：可查看衣柜与收藏，可手动录入衣物；新 AI 推荐和绘图不可用并明确提示。
- 识别失败允许手动选标签；手动标签不意味着断网时也能调用在线推荐。
- 费用限额、超时、并发限制在服务端执行；按钮防重复不作为唯一防护。

## 7. 数据与隐私

本地 IndexedDB 保存：
- 衣物：ID、真实压缩图片、图片摘要、类别／颜色／图案／版型、用户自定名称、创建与修改时间。
- 搭配：起点衣物 ID、标签快照、场景、结构化推荐、关联衣柜 ID、模型／提示版本。
- 收藏：方案快照、必要实物图片与参考图本地数据、创建时间。
- 草稿：待确认状态，与正式衣柜区分。
- 版本号：用于数据迁移。

编辑衣物标签影响未来匹配；已有收藏的历史文字不变。删除衣物后，收藏保留必要快照，但不再标记该条目仍在衣柜。删除确认界面说明这一点；提供独立清空衣柜与收藏的明确操作以便彻底删除本地照片。

照片与密钥不提交到公开 yida 仓库。AI 经服务端调用，密钥不下发浏览器，不记入图片正文日志。应用服务端不主动长期保留用户原图；第三方保留期限、用途与处理地区需选型时核实并告知，不承诺未经核实的零留存。
只有明确保存到衣柜／收藏的数据才作为持久内容保留；不通过 Service Worker 自动缓存 AI 私人响应。前端压缩校验之外，服务端仍须验证上传大小、类型和请求参数。

## 8. 响应式与 PWA

- 360px 手机宽度无横向溢出；桌面用网格展示衣柜与结果。
- 主要点击区域至少 44px，表单具备标签、键盘焦点和可读错误提示。
- 缓存应用外壳；离线读取已保存衣柜、收藏及图片。
- 提供 Manifest、图标及支持浏览器的安装说明；无法安装时仍可用网页。
- 首次加载需要联网；新 AI 能力不宣称离线可用。
- 应用升级不清空衣柜与收藏；迁移失败保留旧数据并提示。
- HTTPS 部署；拍照、存储、安装与离线需手机真机验证。
- 本地存储可能被清理或回收，首版不承诺永久保存或云备份。

## 10. 实施顺序与依赖

1. 页面、真实照片上传、标签确认、本地衣柜及选用流程。
2. 接入视觉识别和文字推荐；完成真实衣柜匹配、字段验证与异常处理。
3. 接入 AI 参考图，控制重复请求、失败重试和费用。
4. 完成收藏、离线与 PWA、测试及真机验证。

AI 供应商、可用地区、费用预算及服务端密钥是开发接入依赖。设计稿不选择付费方案、不产生持续订阅。首版可以用明确标注的模拟数据开发界面，但不能将其宣称为真实 AI 效果。

遵循 AGENTS.md：每次改动创建对应 Git commit，编写或更新相关测试，交付前确保应执行的测试和验证通过。本次仅更新产品设计与验收计划，不包含应用代码。

## 11. 试用与后续方向

邀请 5–10 名用户从一张上衣照片开始试用，再次访问检查：
- 能否看懂裤型、颜色及参考图，并找到自己的相似衣物？
- 自动收录是否清楚，第二次能否直接从衣柜选用？
